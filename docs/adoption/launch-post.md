# Launch Post Draft

I turned a community poll into a reusable skill: `swift-comments-that-matter`.

It helps teams write comments that focus on:
- why code exists
- what must not break
- assumptions, constraints, and side effects

It avoids low-signal comments like “This function does...”, and uses a practical rewrite path:
- no comment
- bad
- good
- best

Includes production-style Swift examples for:
- token refresh concurrency
- download dedup invariants
- payment and pricing rounding constraints
- API contracts and analytics side effects
